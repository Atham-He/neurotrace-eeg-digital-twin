# EMOTIV EPOC X 硬件专项评估框架

> 版本：V0.1
>
> 适用设备：EMOTIV EPOC X
> 用途：为 EEG 实时采集、动态通道展示和后续癫痫样事件分析建立硬件输入可信度门槛。

## 1. 需要验证的七个硬件方面

| ID | 硬件评估方面 | 核心 Metric | 为什么需要验证 | 优先级 |
|---|---|---|---|---|
| HW-01 | 采集精度与时序 | 采样率误差、幅值误差、本底噪声、通道间时序偏差 | 波形幅值、频率和通道先后关系是事件检测与区域判断的基础 | P0 |
| HW-02 | 电极接触与 CMS/DRL 参考 | 合格通道率、准备时间、质量漂移、补液恢复时间、参考故障检出率 | 盐水 felt pads 会随时间干燥，参考接触差可能导致全部通道同时变差 | P0 |
| HW-03 | 无线链路 | 丢包率、断连次数/小时、重连 P95、延迟 jitter | USB Receiver 与 BLE 的稳定性、延迟和续航不同 | P0 |
| HW-04 | 连续运行与数据完整性 | 通道可用率、缺失采样率、最长缺口、长时崩溃数 | 短时间正常不代表能够稳定完成长病例记录 | P0 |
| HW-05 | 电池、温升与断电保护 | 实际续航、告警提前量、表面温升、断电数据损失 | 决定能否覆盖目标采集时长以及是否能安全结束记录 | P1 |
| HW-06 | 佩戴、位置和运动稳定性 | 电极位置偏差、动作后质量下降、伪迹占比、重复佩戴一致性 | 位置和接触变化会同时影响信号质量与脑区侧别解释 | P1 |
| HW-07 | Cortex 数据接口 | `eeg/eq/dev` 更新率、列映射错误率、权限失败识别率、恢复时间 | 设备设置、数据列和 Developer API license 决定程序实际获得什么数据 | P0 |

P0 是接入真实病例前必须验证的项目；P1 可以在初版设备接入完成后继续优化。

## 2. EPOC X 设备基线

正式测试报告必须记录以下配置，不能只写“使用 EPOC X”：

| 配置 | 需要记录的值 |
|---|---|
| 14 个 EEG 通道 | AF3、F7、F3、FC5、T7、P7、O1、O2、P8、T8、FC6、F4、F8、AF4 |
| 参考 | P3/P4 位置 CMS/DRL，或左右乳突替代方案 |
| 采样率 | 128 或 256 SPS |
| 分辨率 | 14 或 16 bit |
| 连接方式 | Proprietary USB Receiver 或 BLE |
| 设备模式 | 固件、headband position、实际 Cortex settings |
| 软件版本 | EMOTIV Launcher、Cortex、程序和固件版本 |
| API 权限 | 可订阅的数据流和 license 类型 |

EPOC X 使用单 ADC 顺序采样，内部采样后降采样为 128/256 SPS；带宽和内置滤波会影响后续预处理，因此算法不能把输入当作完全未处理的宽带原始信号。

## 3. HW-01：采集精度与时序

### 需要测什么

| Metric | 计算/测试方法 | 原因 |
|---|---|---|
| 实际采样率误差 | `|实际样本数/时间 - 配置采样率| / 配置采样率` | 防止频率特征和时间轴随记录长度漂移 |
| 采样间隔 jitter | 样本时间间隔标准差、P95、P99 | 平均采样率正常仍可能存在瞬时抖动 |
| 幅值增益误差 | 信号发生器输入已知 μV 级正弦，比较输出幅值 | 幅值错误会影响尖波阈值和模型特征 |
| 幅值线性 | 多档输入幅值的回归误差 | 确保小信号与大信号均不会失真 |
| 本底噪声 | 标准负载/输入短接下 RMS、峰峰值、噪声谱 | 判断硬件自身是否制造“脑电活动” |
| 通道串扰 | 只向一个输入施加信号，测其他通道响应 | 串扰会产生虚假的多通道同步或传播 |
| 通道间时序偏差 | 各通道输入共同触发信号，比较检测时刻 | EPOC X 为顺序采样，必须确认对事件先后分析的影响 |
| 频带响应 | 频率扫描后测通带增益、截止和相位 | 验证 0.16–43 Hz 与内置滤波对目标波形的影响 |

### 建议测试

1. 128 SPS、256 SPS 分别测试；
2. 14 bit、16 bit 分别测试；
3. 输入正弦、方波、尖峰、混合频率和已知事件时刻；
4. 保存发生器原始设置、Cortex 输出和计算脚本版本；
5. 不用程序自己生成的输出反过来当作硬件真值。

## 4. HW-02：电极接触与 CMS/DRL 参考

EPOC X 的 **contact quality** 与 **EEG quality** 是两个不同指标：

- Contact quality：电极与头皮的接触状态；
- EEG quality：实际 EEG 中噪声和伪迹等综合质量。

程序和报告应分别保存这两个值，不能合并成一个无法解释的“质量分”。

| Metric | 计算/测试方法 | 原因 |
|---|---|---|
| 初始合格通道率 | 佩戴完成时良好/一般/较差通道数 | 判断设备是否具备开始记录的条件 |
| 准备时间 P50/P95 | 从开始佩戴到达到启动门槛 | 评价真实部署效率 |
| Contact quality 漂移 | 每通道每小时质量变化 | 盐水电极会干燥，初始绿色不代表长时稳定 |
| EEG quality 漂移 | 每通道污染时间占比和趋势 | 接触良好也可能有眼电、肌电和运动伪迹 |
| 补液恢复时间 | 从补充 saline 到质量恢复的时间 | 决定中途维护造成的记录中断 |
| CMS/DRL 故障检出率 | 人工制造参考接触差，检查系统能否识别 | 参考异常可能表现为全部通道一起变差 |
| 错误调整率 | 参考异常时系统是否错误要求逐个调整记录电极 | 防止给操作者错误排障建议 |
| 重复佩戴一致性 | 同一受试者多次佩戴的质量和位置差异 | 判断操作人员和佩戴过程的可重复性 |

建议单独设计四个场景：记录电极干燥、单通道脱落、CMS 接触差、DRL 接触差。

## 5. HW-03：无线链路稳定性

USB Receiver 和 BLE 必须分别出报告，不能混合平均。

| Metric | 计算方式 | 原因 |
|---|---|---|
| 包/样本丢失率 | `缺失包或样本 / 预期总数` | 丢失会造成断波和频谱失真 |
| 数据缺口次数 | 每小时大于指定长度的缺口数 | 短而频繁的缺口可能被平均丢包率隐藏 |
| 最长连续缺口 | 每次测试的最大缺口时长 | 判断是否会完整错过事件起始 |
| 断连次数/小时 | 按明确断连定义统计 | 评价真实链路稳定性 |
| 重连时间 P50/P95/P99 | 从断连到稳定数据重新进入系统 | 决定实时系统的恢复能力 |
| 传输 jitter | 到达时间间隔的 P95/P99 | 判断页面是否会周期性卡顿 |
| 距离/遮挡性能曲线 | 不同距离、人体遮挡和房间条件下重复上述指标 | 无线表现高度依赖环境 |

测试场景至少包括：近距离静止、正常桌面距离、人体遮挡、转头/走动、附近有其他 2.4 GHz 设备。

## 6. HW-04：连续运行与数据完整性

| Metric | 计算方式 | 原因 |
|---|---|---|
| 通道可用率 | `有效通道秒数 / 预期通道秒数` | 同时考虑断连、坏接触和无效数据 |
| 缺失采样率 | `缺失样本 / 预期样本` | 直接衡量记录完整性 |
| 最长缺口 | 单次最长无有效数据时间 | 衡量对事件起始捕获的最坏影响 |
| Flatline 时间占比 | 平线持续时间/总时间 | 发现脱落、饱和或链路冻结 |
| 时间戳倒退/重复 | 事件数和涉及样本数 | 会破坏时间轴、窗口和模型输入 |
| 8 小时运行崩溃数 | 固定配置连续运行 | 覆盖典型长时使用与内存泄漏 |
| 内存和延迟漂移 | 第 1 小时与末小时对比 | 发现长时运行逐渐变慢的问题 |

验证时同时保存设备时间、Cortex 时间和程序接收时间，才能判断问题发生在哪一层。

## 7. HW-05：电池、温升与断电保护

官方标称为 USB Receiver 最长约 9 小时、BLE 最长约 6 小时；项目仍需在实际采样率、分辨率和无线方式下重新测量。

| Metric | 原因 |
|---|---|
| 从满电到低电告警的实际时长 | 确定可承诺的采集时长，而不是直接照抄“up to” |
| 从低电告警到关机的时间 P50/P95 | 确保用户有时间保存或更换设备 |
| 不同模式的电量下降曲线 | 256 SPS、BLE 等配置可能改变续航 |
| 表面温升及达到稳定温度的时间 | 与佩戴舒适性和安全相关 |
| 突然断电后的可恢复数据比例 | 防止整个病例文件损坏 |
| 电池状态与 Cortex `dev` 流一致性 | 页面显示的电量必须可信 |

## 8. HW-06：佩戴、位置和运动稳定性

| Metric | 原因 |
|---|---|
| 电极位置偏差 | 通道到左右侧和脑叶的解释依赖位置 |
| 转头、眨眼、说话、咀嚼后的质量下降 | 覆盖现实伪迹而不是只测静止状态 |
| 每类动作的伪迹时间占比 | 为质量门控和伪迹算法提供硬件基线 |
| 设备移位率 | 判断头带能否维持电极位置 |
| 操作者间准备时间和合格率差异 | 发现使用流程是否过度依赖熟练人员 |
| 受试者舒适度和压痛位置 | 决定长时间佩戴是否可行 |

建议至少分层测试不同头围、发量和发质，避免只在少数易佩戴受试者上得到过于乐观的结论。

## 9. HW-07：Cortex 数据接口

| Metric | 计算/验证方式 | 原因 |
|---|---|---|
| `eeg` 实际更新率 | 单位时间收到的样本数 | 验证是否与 128/256 SPS 配置一致 |
| `eq`、`dev` 实际更新率 | 统计数据包到达间隔 | 质量、电池和无线状态不是每个 EEG 样本都更新 |
| 列映射错误率 | 使用 `subscribe` 返回的 `cols` 动态映射并做已知输入测试 | API 列顺序不能被硬编码假设 |
| 通道缺失识别率 | 模拟少列、空值、非数值和断流 | 防止通道错位后继续显示 |
| 权限失败识别率 | 无 raw EEG license 时检查错误状态 | “没有权限”不能被显示成“设备无信号” |
| Session 恢复时间 | Cortex/Launcher 重启后恢复数据的时间 | 实际部署中服务会更新或重启 |
| 凭据泄漏数 | 扫描文件、localStorage、日志和导出 | Client Secret 与 token 不能被保存或输出 |

## 10. 第一版建议门槛

以下是原型阶段的工程候选门槛，正式门槛需在使用场景确认后、测试集解盲前冻结：

| Metric | 候选门槛 | 类型 |
|---|---|---|
| 14 通道名称与左右侧映射 | 错误数 0 | 硬门槛 |
| μV 单位、采样率和时间戳解释 | 错误数 0 | 硬门槛 |
| CMS/DRL 故障注入识别 | 所有预设场景均能识别 | 硬门槛 |
| 低质量通道驱动脑区高亮 | 发生数 0 | 硬门槛 |
| Cortex 权限失败被误报为“无异常” | 发生数 0 | 硬门槛 |
| 台架无线丢包率 | 候选目标 ≤ 0.1% | 工程目标 |
| 自动重连时间 | 候选目标 P95 ≤ 5 秒 | 工程目标 |
| 连续运行 | 8 小时无崩溃、无不可恢复时间轴错误 | 工程目标 |
| 数据列追溯 | 100% 使用当前订阅返回的 `cols` | 硬门槛 |
| 凭据持久化 | Client Secret/token 写入数 0 | 硬门槛 |

人体佩戴下的合格通道率、续航和伪迹占比先通过小规模基线测试建立分布，再依据目标记录时长和允许中断风险确定门槛。

## 11. 推荐执行顺序

1. **台架信号测试**：先确认幅值、频率、噪声和时间戳；
2. **Cortex 接口测试**：确认 `cols`、数据率、权限失败和重连；
3. **静止佩戴测试**：确认接触、CMS/DRL、准备时间和质量漂移；
4. **动作与环境测试**：加入眨眼、转头、说话、走动和无线干扰；
5. **长时测试**：USB Receiver 与 BLE 分别做连续运行和续航；
6. **与程序联调**：验证质量门控、动态通道、时间轴和脑区降级状态；
7. **锁定报告**：保留原始数据、配置、版本、失败案例和复核结论。

## 12. 每次硬件测试需要保存的证据

- 设备 ID、固件、连接方式和 headband position；
- 采样率、分辨率、参考方式和通道列表；
- EMOTIV Launcher、Cortex 和程序版本；
- `subscribe` 返回的每个流的 `cols`；
- 原始数据、接收时间戳、设备状态和质量流；
- 测试环境、距离、动作和操作者；
- Metric 计算脚本版本和原始结果；
- 所有断连、补液、重连、服务重启和人工操作时刻；
- PASS/FAIL、偏差说明和复核人。

---

本专项框架验证的是 EPOC X 作为系统输入端是否可靠。只有硬件与数据质量门槛通过后，才进入癫痫事件检测和脑区概率映射的正式性能验证。
