# EEG 三维可视化平台验证框架设计计划

> 版本：V0.1（框架草案）
>
> 关联文档：[产品概念与页面布局](../README.md)
>
> 首个验证设备：EMOTIV EPOC X；程序架构同时支持其他设备 Profile
> 目的：回答“系统是否采得准、数据是否可信、算法是否有效、脑区表达是否诚实、界面是否会被正确理解”。

## 1. 验证目标

本计划不是只验证最终页面是否能运行，而是从输入到输出逐层验证：

```text
硬件与电极
    ↓
原始 EEG 数据质量
    ↓
预处理与时间同步
    ↓
癫痫样事件识别
    ↓
动态通道选择
    ↓
脑区级概率映射
    ↓
三维可视化与用户理解
    ↓
端到端系统、隐私与实际使用
```

上游未通过时，下游结果不能被视为有效。例如信号质量不足时，即使模型输出了高置信脑区，也必须触发降级或拒绝输出，而不是继续显示强烈红色热区。

## 2. 验证原则

### 2.1 Verification 与 Validation 分开

- **Verification（实现核验）**：系统是否按照规格正确采集、计算、同步和显示；
- **Validation（有效性验证）**：这些输出是否真的对目标用户和目标场景有意义，是否会造成错误理解。

### 2.2 每项产品主张都必须可追溯

每项主张必须绑定：

```text
产品主张 → 风险 → 验证问题 → Metric → 测试数据/设备 → 通过阈值 → 证据报告
```

例如：

```text
“系统能突出重要且可靠的通道”
→ 可能隐藏关键通道或展示伪迹通道
→ Top-K 是否覆盖专家认可的关键通道？低质量通道是否被错误选入？
→ Top-K evidence recall + bad-channel leakage rate
→ 带通道质量和专家标注的独立病例测试集
→ 阈值在测试集锁定前确定
→ CHANNEL-SELECT-REPORT
```

### 2.3 不使用单一总分掩盖失败

硬件稳定、数据质量、事件检测、脑区映射和用户理解分别设门槛。某一层的高分不能抵消另一层的严重失败。

### 2.4 同时报告平均表现与最差场景

所有关键指标至少按以下粒度报告：

- 总体；
- 每位受试者/病例；
- 不同设备或电极配置；
- 不同信号质量等级；
- 不同事件类型；
- 不同中心或数据来源（如适用）。

除点估计外，应报告置信区间。类别不平衡场景不能只报告 accuracy。

## 3. 验证方面总览

| 方面 | 核心问题 | 主要输出 | 优先级 |
|---|---|---|---|
| A. 硬件与采集 | 电极和设备是否稳定、准确地采到 EEG？ | 硬件台架与佩戴测试报告 | P0 |
| B. 数据质量 | 数据是否完整、低噪、可用于分析？ | 通道质量与伪迹报告 | P0 |
| C. 预处理与同步 | 滤波是否失真？各模块时间是否一致？ | 信号处理与时钟同步报告 | P0 |
| D. 事件识别算法 | 是否能发现事件，并控制误报和延迟？ | 独立测试集算法报告 | P0 |
| E. 动态通道选择 | 是否展示可靠且重要的通道，同时保持稳定？ | 通道选择验证报告 | P0 |
| F. 脑区概率映射 | 区域推测是否达到声明的粒度并表达不确定性？ | 脑区映射验证报告 | P0/P1 |
| G. 可视化与人因 | 用户能否正确、快速且不过度解读结果？ | 可用性与理解度报告 | P1 |
| H. 系统性能与可靠性 | 端到端是否实时、稳定、可恢复、可追溯？ | 系统与压力测试报告 | P0 |
| I. 泛化与鲁棒性 | 换人群、设备、噪声后是否仍可信？ | 分层及外部验证报告 | P1 |
| J. 数据治理与安全 | 病例数据是否被正确保护和审计？ | 隐私、安全与权限报告 | P1/上线前 P0 |
| K. 临床/研究使用价值 | 系统是否帮助目标用户而不引入新的风险？ | 盲法用户研究或前瞻试验报告 | P2 |

## 4. 各方面验证指标

### A. 硬件与采集

#### A0. EPOC X 验证基线

本项目当前指定设备为 EMOTIV EPOC X，验证配置以设备实际运行设置为准：

| 项目 | EPOC X 基线 | 对验证的影响 |
|---|---|---|
| EEG 通道 | AF3、F7、F3、FC5、T7、P7、O1、O2、P8、T8、FC6、F4、F8、AF4 | 所有通道选择、侧别和脑叶映射均使用该固定布局 |
| 参考电极 | P3/P4 位置的 CMS/DRL；可选左右乳突替代 | 参考接触不良可能导致全部记录通道同时变差，必须单独监控 |
| 电极材料 | 盐水浸润 felt pads | 需要验证干燥、补液、长时佩戴和头发造成的质量漂移 |
| 采样方式 | 单 ADC 顺序采样，内部 2048 Hz | 需要验证或确认通道间采样时序及同步影响 |
| 输出采样率 | 用户配置为 128 或 256 SPS | 数据协议、滤波、窗口、延迟和模型必须记录实际配置 |
| 分辨率 | 14/16 bit 用户配置 | 幅值量化与噪声测试必须按实际模式分层 |
| 带宽与滤波 | 0.16–43 Hz；50/60 Hz 数字陷波；内置 5 阶 Sinc filter | 后续预处理不能假设输入仍是完全未滤波信号 |
| 无线连接 | Proprietary USB Receiver 或 BLE | 两种连接方式分别报告丢包、延迟、重连和续航 |
| Cortex 数据 | `eeg`、`eq`、`dev` 等流，具体能力受设备设置与 license 影响 | 接口测试需覆盖权限不足、订阅失败和列顺序动态返回 |

官方规格与接口参考：[EPOC X 技术规格](https://www.emotiv.com/epoc-x)、[Cortex Data Subscription](https://emotiv.gitbook.io/cortex-api/data-subscription)。

EPOC X 的 contact quality 和 EEG quality 是两个不同指标：前者用于判断电极接触，后者反映 EEG 信号质量。验证和界面不能将二者合并成一个含义不明的“质量分”。

#### A1. 通道连接与连续采集能力

| 验证问题 | Metric | 计算/记录方式 | 为什么 |
|---|---|---|---|
| 预期通道是否持续在线？ | 通道可用率 | `有效通道秒数 / 预期通道秒数 × 100%` | 通道缺失会改变空间覆盖和模型输入 |
| 数据传输是否丢失？ | 丢包率、缺失采样率 | `丢失包或采样点 / 预期总数` | 丢包会造成波形断裂、频谱失真和假异常 |
| 是否频繁断连？ | 断连次数/通道小时 | 按通道和整机统计 | 平均可用率可能掩盖频繁短断连 |
| 断连后多久恢复？ | 自动恢复时间 P50/P95/P99 | 从断连到稳定数据恢复 | 实时监测必须知道最坏恢复时间 |
| 是否可长时间运行？ | 无故障连续运行时间、崩溃次数 | 4/8/24 小时连续压力测试 | 短 demo 正常不代表真实使用稳定 |

#### A2. 采集精度与电气性能

| 验证问题 | Metric | 测试方法 | 为什么 |
|---|---|---|---|
| 幅值是否准确？ | 增益误差、线性误差、直流偏置 | 信号发生器输入已知幅值与频率 | 幅值错误会影响阈值、特征和临床观察 |
| 时间轴是否准确？ | 实际采样率误差、采样间隔 jitter | 高精度参考信号/时钟对比 | 采样率漂移会影响频率与事件时间定位 |
| 本底噪声是否足够低？ | 输入短接 RMS/峰峰值噪声、噪声谱密度 | 输入短接或标准负载台架测试 | 硬件噪声可能被误判为脑电活动 |
| 通道之间是否串扰？ | 通道串扰比 | 单通道输入、其他通道静默 | 串扰会制造虚假的多通道传播 |
| 工频和共模抑制能力如何？ | 工频抑制、CMRR | 标准共模输入测试 | 50/60 Hz 干扰是常见现实问题 |
| 频带是否符合设计？ | 通带增益、截止频率、相位/群延迟 | 频率扫描 | 频带失真会改变尖波和节律形态 |

通过门槛应来自硬件规格、目标采样率、目标 EEG 频带和风险分析；这些参数确定后，必须在正式测试前锁定。

#### A3. 电极接触与佩戴

| 验证问题 | Metric | 测试方法 | 为什么 |
|---|---|---|---|
| 是否能快速达到可采集状态？ | 佩戴到可用时间 P50/P95 | 多操作者、多头型重复佩戴 | 直接影响实际可用性 |
| 接触是否稳定？ | 阻抗/接触质量合格率及随时间漂移 | 静息、转头、说话、走动场景 | 接触变化是信号质量波动的主要来源之一 |
| 接触质量读数是否可信？ | 与参考阻抗或人工质量评级的相关性/一致性 | 同步测量并盲评 | 错误的绿色状态会让坏数据进入模型 |
| 电极位置是否偏移？ | 位置偏差（mm 或相对头围比例） | 标准定位或摄影测量 | 位置偏差会影响通道到脑区的映射 |

#### A4. 无线、电源、热与机械稳定性

| 验证问题 | Metric | 为什么 |
|---|---|---|
| 典型与最坏场景续航是否足够？ | 续航时间、低电量告警提前量 | 断电会造成数据中断 |
| 不同距离/遮挡下是否稳定？ | 丢包率、延迟、重连时间随距离变化 | 无线环境会显著改变实时表现 |
| 设备温升是否可接受？ | 表面温升与时间曲线 | 与佩戴舒适性和安全相关 |
| 日常动作下是否松动？ | 移位率、连接中断率、运动伪迹增长量 | 实验室静止测试不足以覆盖真实使用 |

若设备属于自研硬件，电气安全、生物相容性和结构安全需另设专项计划，并由具备资质的流程验证；本框架不以软件测试代替这些验证。

### B. 数据质量

#### B1. 完整性与有效范围

| 验证问题 | Metric | 为什么 |
|---|---|---|
| 数据有没有缺口？ | 缺失采样比例、最长连续缺口、缺口次数/小时 | 短缺口也可能刚好覆盖事件起始 |
| 是否出现平线？ | flatline 时间占比、平线事件数 | 平线通常代表脱落、饱和或链路异常 |
| 是否削顶或饱和？ | clipping/saturation 时间占比 | 削顶会改变波形形态和频谱 |
| 单位和范围是否正确？ | 单位错误数、超物理/设备范围样本数 | μV/V 混淆会造成灾难性输入错误 |
| 通道名称和导联是否正确？ | montage 映射错误率 | 错误映射会直接造成错误脑区侧别 |

通道名称、采样率、单位、参考方式和电极位置属于硬门槛元数据；关键字段缺失时，该记录不得进入正式模型评估。

#### B2. 噪声和信噪比

| 验证问题 | Metric | 为什么 |
|---|---|---|
| 基线噪声多大？ | 基线 RMS、峰峰值、频段功率 | 判断数据是否超过硬件和环境噪声基线 |
| 工频污染多大？ | 50/60 Hz 功率占比及其谐波 | 工频可掩盖或模拟节律变化 |
| 高频肌电污染多大？ | 预定义高频段功率占比 | 肌电可能制造高频异常外观 |
| 信号是否足够可辨识？ | SNR 或相对基线 SNR | 量化“看起来还行”之外的可用程度 |
| 通道间是否出现异常高相关？ | 通道相关矩阵异常率 | 可能提示桥接、公共参考污染或串扰 |

频段边界需根据目标人群、设备带宽和算法定义后锁定，不能在看到测试结果后调整。

#### B3. 伪迹识别能力

| 伪迹类型 | Metric | 为什么 |
|---|---|---|
| 眨眼/眼动 | sensitivity、precision、F1、误报次数/小时 | 额区伪迹可能被误认作额区异常 |
| 肌电 | sensitivity、precision、F1、覆盖时间误差 | 肌电可造成高频、大幅活动 |
| 运动/电极弹跳 | sensitivity、precision、F1、检测延迟 | 突变可能触发假报警 |
| 工频干扰 | 检出率、频率估计误差 | 决定是否需要滤波或提示环境问题 |
| 电极脱落/平线 | sensitivity、恢复识别时间 | 防止断开通道继续参与分析 |

伪迹标签需由明确规则、参考传感器或至少两位受训标注者建立。只用算法自己生成的标签验证算法本身会形成循环验证。

#### B4. 通道质量评分是否可靠

| 验证问题 | Metric | 为什么 |
|---|---|---|
| 能否识别不可用通道？ | sensitivity、specificity、AUROC、PR-AUC | 质量评分是所有下游模块的入口门 |
| “80 分”是否真的比“60 分”可靠？ | Brier score、ECE、可靠性曲线 | 分数需要可解释，而不只是排序 |
| 与专家判断是否一致？ | Cohen/Fleiss kappa、分歧矩阵 | 判断自动质量分级是否符合人工标准 |
| 不同伪迹下是否稳定？ | 分伪迹类型的召回率与误报率 | 总体平均会掩盖薄弱类型 |

### C. 预处理与时间同步

#### C1. 滤波、重参考和分窗正确性

| 验证问题 | Metric | 为什么 |
|---|---|---|
| 滤波后幅值是否失真？ | 通带幅值误差、阻带衰减 | 尖波可能被过度削弱或增强 |
| 是否引入时间偏移？ | 相位偏移、群延迟、事件峰值偏移 | 会影响异常起始和跨模态同步 |
| 边界是否产生假波形？ | 窗口边缘伪迹率 | 分块处理可能制造假尖波 |
| 离线与实时结果是否一致？ | 波形误差、特征误差、事件输出一致率 | 防止原型回放有效、实时接入失效 |
| 重参考是否映射正确？ | 已知输入下的数值对照测试 | 导联错误会改变侧别和空间判断 |

每种预处理配置必须带版本号，并保存参数、代码版本和输入数据校验值，使同一输入能够复现同一输出。

#### C2. 模块时间同步

| 同步对象 | Metric | 为什么 |
|---|---|---|
| EEG 与设备时间 | 时钟偏差、漂移率 | 决定原始记录是否可信 |
| EEG 与事件检测 | 检测输出时间戳误差 | 决定异常框是否落在正确波形上 |
| EEG 与三维热区 | 游标偏差 P50/P95 | 错位会让用户建立错误因果关系 |
| EEG 与视频/其他模态 | 对齐误差、长时间漂移 | 多模态复核依赖统一时间轴 |
| 前端与后端 | 网络与渲染延迟分解 | 区分算法慢、传输慢还是页面慢 |

同步测试使用共同触发信号或可识别脉冲，不只依赖肉眼观看。

### D. 癫痫样事件识别算法

首先必须锁定目标：检测的是临床发作、发作起始、发作间期放电，还是更宽泛的“异常 EEG”。不同目标不能混用同一组标签和指标。

#### D1. 是否检测到事件

| 验证问题 | Metric | 为什么 |
|---|---|---|
| 真实事件有多少被检测？ | event-level sensitivity/recall | 漏检是核心风险之一 |
| 报警中有多少是真的？ | event-level PPV/precision | 用户不能被大量假报警淹没 |
| 每小时产生多少误报？ | false alarms per hour | 比总体 specificity 更接近长时监测体验 |
| 样本级区分能力如何？ | PR-AUC、ROC-AUC、macro F1 | PR-AUC 更适合事件稀少的数据 |
| 每位患者表现是否稳定？ | patient-level macro 指标、最差分位 | 防止少数长记录主导总体结果 |

事件匹配规则必须预先定义，例如预测与专家事件需要多少重叠才算命中；否则 sensitivity 可以通过无限延长预测区间被人为提高。

#### D2. 事件时间是否准确

| 验证问题 | Metric | 为什么 |
|---|---|---|
| 起始点偏差多大？ | onset MAE、median、P95、提前/延迟分布 | 决定时间轴和脑区动画是否可信 |
| 结束点偏差多大？ | offset MAE、median、P95 | 决定事件持续时间是否可靠 |
| 事件区间重叠程度如何？ | temporal IoU/Dice | 同时评价开始与结束 |
| 实时报警有多慢？ | detection latency P50/P95/P99 | 离线准确不代表实时可用 |

#### D3. 置信度是否可信

| Metric | 目的 |
|---|---|
| Brier score / log loss | 评价概率预测而不只看分类结果 |
| ECE 与可靠性图 | 检查“80% 置信度”是否接近实际正确率 |
| selective risk / coverage | 验证模型在不确定时拒绝输出能否减少错误 |
| 不同质量等级下的校准误差 | 防止低质量数据仍给出虚假高置信度 |

#### D4. 评估设计

- 按受试者划分训练、验证、测试集，禁止同一受试者片段跨集合泄漏；
- 调参只使用训练/验证集，最终测试集锁定后只运行一次正式评估；
- 由至少两位合格标注者独立标注并处理分歧；
- 同时保留正常、伪迹、非癫痫异常和目标事件；
- 报告病例数、总时长、事件数及置信区间，而不只报告样本窗口数。

### E. 动态通道选择

动态通道选择包含两个独立问题：先判断“这个通道是否可靠”，再判断“这个可靠通道是否与当前事件相关”。质量和相关度不能直接混成一个不透明总分。

| 验证问题 | Metric | 计算方式 | 为什么 |
|---|---|---|---|
| 关键通道是否出现在主视图？ | Top-K evidence recall | 专家关键通道中出现在 Top-K 的比例 | 动态展示不能隐藏重要证据 |
| 坏通道是否错误进入主视图？ | bad-channel leakage rate | Top-K 中不可用通道比例 | 伪迹通道可能误导用户和模型 |
| 被隐藏通道是否仍可访问？ | channel accessibility rate、展开成功率 | 任务测试 | “省略”不能变成数据不可见 |
| 事件发生后多久突出相关通道？ | selection latency P50/P95 | 从事件起始到进入 Top-K | 太慢会错过起始证据 |
| 通道是否频繁跳动？ | reorder/churn 次数每分钟、平均驻留时间 | 连续回放统计 | 频繁换行会破坏视觉连续性 |
| 排名是否抗小扰动？ | rank correlation、Top-K Jaccard | 对输入加入小幅噪声或轻微阻抗变化 | 防止界面因微小变化不断闪动 |
| 用户固定通道是否始终保留？ | pin persistence pass rate | 自动化交互测试 | 人工控制必须高于自动排序 |
| 左右侧/区域覆盖是否偏置？ | 各侧别、各脑叶入选率及条件表现 | 分层统计 | 发现电极布局或算法造成的系统性偏差 |

建议的选择逻辑：

1. 不可用通道进入折叠区并标注原因，默认不参与脑区推测；
2. 合格通道按事件相关度排序；
3. 达到稳定持续时间后才调整显示顺序；
4. 人工固定通道不被自动替换；
5. 当合格通道不足时，停止强脑区显示并明确提示数据不足。

以下三项建议设为硬门槛：低质量通道不得静默驱动脑区高亮；全部通道必须可访问；人工固定状态必须被保留。

### F. 脑区概率映射

#### F1. 先锁定允许声明的空间粒度

V0.1 建议只验证并声明：

- 左/右半球；
- 额、颞、顶、枕等脑叶级区域；
- “疑似主要涉及区域”及其置信度。

如果没有适当参考标准，不验证也不显示毫米级坐标、具体脑回或确定性深部结构起源。

#### F2. 区域正确性

| 参考标准可提供的标签 | Metric | 为什么 |
|---|---|---|
| 半球标签 | balanced accuracy、sensitivity、specificity | 最基础且更可能可靠的空间结论 |
| 脑叶标签 | macro F1、Top-1 accuracy、Top-K recall | 兼顾类别不平衡与候选区域输出 |
| 多区域标签 | region-level precision/recall、macro F1 | 一个事件可能涉及多个区域 |
| 区域掩膜 | Dice/IoU、质心距离 | 仅在参考标准支持空间掩膜时使用 |
| 概率分布 | Brier/ECE、rank correlation | 检查热图强度和置信度是否有意义 |

参考标准的优先级应在研究方案中明确，可包括专家对头皮 EEG 的区域判断，以及在具备条件时使用的影像、手术评估或颅内电极结果。不同参考标准回答的问题不同，不能混成一个“真值”。

#### F3. 不确定性与降级行为

| 验证问题 | Metric | 为什么 |
|---|---|---|
| 低质量时是否降低置信度？ | 质量下降前后的置信度变化、错误高置信率 | 防止坏数据产生漂亮但虚假的热图 |
| 不确定时是否拒绝输出？ | abstention sensitivity、coverage-risk 曲线 | 拒绝输出优于错误精确定位 |
| 热区是否抗轻微扰动？ | heatmap Dice/Jaccard、分布距离 | 检查模型稳定性 |
| 移除关键通道后会怎样？ | 区域输出变化、置信度下降幅度 | 验证结果是否依赖合理证据 |
| 结果是否可追溯？ | 区域到证据通道/时间窗追溯率 | 用户需要知道红色区域来自什么证据 |

“区域—证据通道—时间窗—模型版本”的追溯率建议为 100%。不能追溯的区域不应显示为正式结果。

#### F4. 传播动画

若当前只有静态区域分类结果，传播动画只能标注为演示效果。只有在算法确实输出经验证的区域时序后，才验证并展示：

- 区域激活先后顺序一致率；
- 区域间延迟误差；
- 传播阶段识别准确率；
- 不同重复运行的路径稳定性。

### G. 可视化与人因

#### G1. 功能和同步正确性

| 验证问题 | Metric | 为什么 |
|---|---|---|
| 波形、时间轴和脑模型是否同一时刻？ | 跨组件时间偏差 P50/P95 | 避免视觉上制造错误关联 |
| 区域名称与模型网格是否一致？ | 解剖映射测试通过率 | 防止左右、前后或脑叶映射错误 |
| 状态颜色和文字是否一致？ | 状态一致性测试通过率 | 防止页面不同区域显示互相冲突的信息 |
| 异常框是否覆盖正确事件？ | 显示区间与后端结果 IoU | 验证前端没有二次偏移 |

时间同步、左右侧映射和数据单位错误属于零容忍缺陷。

#### G2. 可用性与理解度

| 用户任务 | Metric | 为什么 |
|---|---|---|
| 找到当前重要通道 | 任务成功率、完成时间、错误点击数 | 验证动态排序是否真正降低负担 |
| 查看被折叠通道 | 成功率、完成时间 | 确保非主通道没有被隐藏 |
| 找到事件起始和持续区间 | 时间误差、任务时间 | 验证时间轴与异常框是否清晰 |
| 判断结果是否只是模型推测 | 正确理解率 | 防止把热区误读成临床确诊 |
| 识别低质量/数据不足状态 | 正确理解率和反应时间 | 防止继续信任不可靠输出 |
| 完成病例回放 | SUS、NASA-TLX、主观信任与依赖问卷 | 评价整体易用性、负担和信任校准 |

必须专门测试“过度信任”：向用户展示一个高置信但带数据不足提示的案例，观察其是否仍把红色热区当成确定结论。

#### G3. 视觉可访问性

- 文本与背景对比度；
- 色觉缺陷模拟下的状态识别率；
- 不依赖红/绿颜色单独传递信息；
- 缩放和不同屏幕尺寸下的可读性；
- 波形高密度时标签、单位和时间刻度是否仍清楚。

### H. 系统性能与可靠性

#### H1. 端到端性能

| Metric | 分解方式 | 为什么 |
|---|---|---|
| 端到端延迟 P50/P95/P99 | 采集→预处理→推理→传输→渲染 | 平均值会掩盖偶发卡顿 |
| EEG 渲染帧率与掉帧率 | 不同通道数、窗口长度、设备性能 | 保证波形连续可读 |
| 三维模型帧率 | 默认/旋转/热区更新分别测试 | 三维视觉是核心交互 |
| CPU/GPU/内存占用 | 空闲、正常、事件高峰、长时运行 | 发现资源泄漏和低配设备风险 |
| 最大稳定通道数与采样率 | 压力测试 | 明确系统容量边界 |

#### H2. 故障、恢复与可追溯

| 场景 | Metric | 为什么 |
|---|---|---|
| 网络中断 | 数据丢失量、恢复时间、重复数据率 | 实时系统必须可恢复 |
| 服务重启 | 状态恢复时间、时间轴连续性 | 防止病例上下文丢失 |
| 模型异常/超时 | 降级显示正确率、错误提示率 | 算法失败不能伪装成“无异常” |
| 数据格式错误 | 拒绝率、错误定位准确率 | 输入错误必须可解释地失败 |
| 长时运行 | 崩溃数、内存增长率、延迟漂移 | 发现短测试看不到的问题 |
| 结果复现 | 同输入同版本输出一致率 | 支持研究复核和审计 |
| 审计记录 | 数据/模型/配置/操作者追溯完整率 | 能解释某次结果如何产生 |

“模型不可用”与“未检测到异常”必须是两个不同状态，并有自动化测试覆盖。

### I. 泛化与鲁棒性

| 变化因素 | Metric | 为什么 |
|---|---|---|
| 不同受试者 | 每人指标分布、最差分位 | EEG 个体差异大 |
| 不同中心/设备 | 性能差异和置信区间 | 发现域偏移 |
| 不同通道数量/布局 | 检测与区域性能下降幅度 | 实际设备配置可能不同 |
| 不同参考方式 | 性能下降幅度、是否需重校准 | 导联定义会改变波形 |
| 不同噪声与缺失通道 | 性能曲线、拒绝输出率 | 验证渐进降级而非突然失效 |
| 不同事件类型 | 分类型 sensitivity/PPV/F1 | 总体平均会掩盖某类失效 |
| 非目标异常和伪迹 | false alarms/hour | 验证真实误报负担 |

推荐使用扰动强度—性能曲线，而不是只测试“干净”和“极差”两个点。系统应随质量下降逐渐降低置信度或拒绝输出。

### J. 数据治理与安全

| 验证问题 | Metric/门槛 | 为什么 |
|---|---|---|
| 病例是否正确脱敏？ | 测试数据中直接身份标识残留数为 0 | 患者数据风险高 |
| 权限是否正确？ | 未授权读取/导出成功数为 0 | 防止越权访问 |
| 传输与存储是否受保护？ | 配置检查、密钥/明文扫描通过率 | 防止数据泄露 |
| 谁看过或改过结果能否追溯？ | 关键操作审计覆盖率 100% | 支持责任追踪 |
| 删除和保留策略是否生效？ | 到期删除成功率、备份一致性 | 避免无限期保存敏感数据 |
| 导出是否携带多余信息？ | 导出字段白名单通过率 | 报告和截图也可能泄露身份信息 |

正式使用前需根据目标地区、机构政策和产品定位补充合规评估；本框架只提供技术验证入口。

### K. 临床/研究使用价值

该层在前述技术层通过后进行，不能用用户“觉得很酷”替代算法有效性。

| 研究问题 | Metric | 建议设计 |
|---|---|---|
| 是否缩短病例浏览时间？ | 每例复核时间、中位节省时间 | 同一用户交叉对照 |
| 是否提高事件发现能力？ | 用户级 sensitivity、PPV、false alarms/hour | 无辅助 vs 有辅助盲法比较 |
| 是否提高区域判断一致性？ | 与参考标准一致率、用户间 kappa | 仅在脑叶级声明范围内评价 |
| 是否造成自动化偏见？ | 错误模型提示下的跟随率 | 有意加入受控错误案例 |
| 用户是否正确校准信任？ | 高/低质量场景下的采纳率 | 检查提示是否改变决策 |

若未来定位为临床辅助工具，需要独立的临床验证方案、统计分析计划和伦理/合规流程，本计划不能替代这些工作。

## 5. 测试数据与场景矩阵

正式测试集至少覆盖以下组合，而不是只选一段效果最明显的病例：

| 维度 | 建议分层 |
|---|---|
| 数据模式 | 文件回放、设备实时流、断线后恢复 |
| 信号状态 | 良好、一般、部分通道差、全部不足 |
| 事件状态 | 正常、目标事件、非目标异常、伪迹 |
| 事件阶段 | 基线、起始、增强/扩散、恢复 |
| 通道情况 | 全通道、随机缺失、关键通道缺失、错误映射 |
| 佩戴状态 | 静息、眨眼、咀嚼/说话、转头、行走（若适用） |
| 系统状态 | 正常、网络抖动、推理超时、服务重启、低性能终端 |
| 数据来源 | 开发数据、独立内部测试、外部中心/设备（后期） |

数据集清单需记录：病例数、总时长、事件数、每类伪迹时长、设备、通道布局、采样率、参考方式、人口学分层和标签来源。

样本量由目标指标、预期效应和允许置信区间宽度计算后确定，不以“窗口数很多”代替足够的患者数。

## 6. 通过阈值如何确定

当前缺少设备规格、使用场景和目标事件定义，因此 V0.1 不为所有指标填入任意数字。阈值采用以下来源，并在正式测试前冻结：

1. **零容忍门槛**：左右侧映射错误、单位错误、时间戳错位、患者级数据泄漏、未授权访问等；
2. **硬件规格门槛**：采样率、噪声、带宽、续航、阻抗范围等；
3. **风险门槛**：根据漏检、误报、延迟和错误高置信结果的后果确定；
4. **对照基线**：与现有算法、固定通道页面或人工流程比较；
5. **用户目标**：任务成功率、完成时间和正确理解率；
6. **统计门槛**：关键指标使用置信区间下界/上界判定，不只看点估计。

建议先确定的工程硬门槛：

- 所有正式测试必须无受试者级训练/测试泄漏；
- 低质量数据不得静默产生高置信脑区正式结果；
- EEG、事件框、脑区热图必须使用同一可追溯时间基准；
- 左右侧、脑区名称、通道单位和 montage 映射错误为 0；
- 所有脑区结果都能追溯到时间窗、证据通道、模型和配置版本；
- 模型超时/失败不得显示成“未发现异常”；
- 自动结果和人工标注必须可区分。

## 7. 分阶段执行计划

### Phase 0：锁定主张与测试口径

产出：

- Intended Use/目标使用场景；
- 目标事件定义；
- 设备与通道规格；
- 脑区声明粒度；
- 标签和参考标准；
- Metric Registry V1；
- 风险清单与测试优先级。

退出条件：每项页面主张均能找到验证指标；所有 P0 指标有计算口径、数据源和阈值负责人。

### Phase 1：台架与合成数据验证

验证 A、B、C、G 的确定性功能和 H 的基础性能。使用信号发生器、合成波形、已知时间脉冲、断连和错误格式注入。

退出条件：采集、单位、通道映射、滤波、时间同步、前端映射等基础链路通过；零容忍缺陷为 0。

### Phase 2：离线脱敏病例验证

验证 D、E、F、I。使用锁定的患者级独立测试集，生成事件级、病例级和分层报告。

退出条件：核心算法指标达到预设门槛；无数据泄漏；失败案例已归类；低质量降级行为通过。

### Phase 3：高保真界面与用户验证

验证 G 和 K 的早期问题。让目标用户完成固定任务，并测试误导性场景、低质量场景和模型失败场景。

退出条件：关键任务成功率和正确理解率达到预设门槛；无未缓解的高风险误解。

### Phase 4：实时设备小规模试运行

验证 A–I 的端到端表现，包括长时运行、网络异常、重连、动态通道变化和实时延迟。

退出条件：连续运行和恢复指标达标；实时结果与离线参考保持在允许差异内；审计信息完整。

### Phase 5：外部/临床验证（如进入相应用途）

使用独立中心、设备或前瞻数据验证泛化和实际使用价值，单独制定统计、伦理和合规方案。

## 10. 当前需要尽快锁定的问题

这些问题决定具体 metric 阈值和测试集设计：

1. 设备是现成硬件还是自研硬件？有多少通道、什么电极布局？

8. 主要用户是算法研究人员、医生、技师还是面向展示的非专业用户？
9. 病例数据规模、事件数、设备来源和标签质量如何？

## 11. 第一轮 P0 验证 Backlog

在上述问题尚未全部确定前，可以立即启动以下工作：

- 建立统一的通道、采样率、单位、montage 和时间戳数据协议；
- 建立带已知频率/幅值/事件时刻的合成 EEG 数据；

- 建立通道质量标签规范和专家复核表；
- 建立患者级数据切分与泄漏检查；
- 确定事件匹配规则并实现 event-level sensitivity、PPV、false alarms/hour；
